# 26.08 — Dependency lockfile enforcement

## Goal

Make dependency resolution reproducible and fail closed in CI.

## Contract

- npm is the canonical package manager.
- `package-lock.json` is required at repository root.
- lockfile version is 3 and must match the root package manifest/workspaces.
- CI installs dependencies with `npm ci --no-audit --no-fund`, never a resolving install.
- the Node setup cache is keyed from `package-lock.json`.
- registry package entries carrying a resolved tarball must also carry integrity metadata.
- a lockfile or CI contract mismatch blocks GREEN.

## Evidence boundary

The canonical lockfile was generated by GitHub Actions from the exact PR manifest and successfully consumed by `npm ci` before it was promoted into the branch. The temporary bootstrap workflow is removed before merge; permanent enforcement remains in the standard verification workflow and system pre-gates.
